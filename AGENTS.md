# AGENTS.md — ergogenesis

A split, ZMK-powered, Choc-spaced ergonomic keyboard generated with
[Ergogen](https://github.com/ergogen/ergogen) and routed in KiCad 8 + Freerouting.

## Current focus

PCB design. The primary file under active iteration is:

- `ergogen/config.yaml` — the single Ergogen input that produces points,
  outlines, and the KiCad PCB.

ZMK firmware lives alongside (`zmk/`, `firmware/`, `config/`, `modules/`,
`zephyr/`) but is **not** the current focus. Do not touch firmware code unless
explicitly asked.

## Building / iterating

All commands run from `ergogen/` unless noted.

```bash
# one-shot build (writes to ergogen/output/)
pnpm run ergogen:build
# or
just ergogen-build

# watch mode: rebuild on changes to config.yaml or footprints/*.js
just ergogen-watch

# preview a generated outline (DXF)
just visualize-dxf ./output/outlines/<name>.dxf
```

`config.yaml` is annotated with `# yaml-language-server: $schema=...` pointing at
the upstream Ergogen schema — keep that intact so editors give completions.

## Editing `config.yaml`

Top-level sections, in order:

1. `meta` — engine version pin (`4.1.0`, required for KiCad 8 footprints), name,
   author.
2. `units` — Choc spacing (`cx=18mm`, `cy=17mm`), padding, MCU envelope, screw
   sizes, reset switch size. **Prefer adding a unit over hard-coding mm.**
3. `points` — zones / columns / rows / key splay & stagger. This drives
   everything downstream.
4. `outlines` — boolean-composed shapes built from `points`. Outputs `.dxf` in
   `output/outlines/`.
5. `pcbs` — single PCB `shield-pcb`. `template: kicad8` is required. References
   footprints from `./footprints/ceoloide/` and `./footprints/imochoa/`.

When changing keys/columns:

- Run `ergogen-watch` and check `output/outlines/*.dxf` visually before touching
  PCB footprints.
- Net names (e.g. `col_net`, `row_net`) are wired in the `pcbs.*.footprints`
  section — keep them consistent with the matrix you want ZMK to see later.
- A lot of footprint blocks in `pcbs:` are commented out (button, JST, mounting
  holes, silkscreen text, front/back images). Uncomment and adjust paths
  relative to `ergogen/` (e.g. `./footprints/imochoa/mountinghole.js`).

Reference configs to crib from:

- `ergogen/sweep-like-minimal.yaml` — minimal direct-pin + GND sweep-like setup
  (ceoloide).
- `ergogen/old-config.yaml` — previous iteration of this board.
- See README.md for upstream inspiration links (corney-island,
  ceoloide/ergogen-footprints, flatfootfox tutorials).

## Footprints

- **Upstream** (do not modify): `ergogen/footprints/ceoloide/*.js` — pulled from
  https://github.com/ceoloide/ergogen-footprints. If something is missing,
  prefer adding the upstream file over rewriting it.
- **Local** (free to modify): `ergogen/footprints/imochoa/*.js`.
- Ergogen footprint API: https://docs.ergogen.xyz/footprint-format/

## PCB / routing workflow

After `ergogen:build`:

1. Open `ergogen/output/pcbs/shield-pcb.kicad_pcb` in KiCad 8 `pcbnew`.
2. Save once so KiCad upgrades the file format.
3. `File > Export > Specctra DSN` → save next to the `.kicad_pcb`.
4. Auto-route with Freerouting:
   ```bash
   just kicad-freerouting-gui
   ```
   (uses `output/manual/shield-pcb.dsn` → `shield-pcb-routed.ses`,
   `-inc GND`, single thread, optimizer maxed).
5. In KiCad: `File > Import > Specctra Session` to pull routes back in.
6. Sanity checks / artifacts:
   ```bash
   just kicad-checks         # DRC
   just kicad-export-pdf     # front/back PDFs
   ```

## Conventions for agents

- Treat `ergogen/config.yaml` as the source of truth. Do not hand-edit generated
  files in `ergogen/output/` or the `.kicad_pcb` — regenerate instead.
- Keep YAML indentation at 2 spaces (matches existing file).
- Preserve the schema comment on line 1 of `config.yaml`.
- When suggesting changes, show small diffs of `config.yaml` and call out which
  output files will change (`outlines/*.dxf`, `pcbs/shield-pcb.kicad_pcb`).
- Use units (`kx`, `ky`, `px`, `py`, `U`, etc.) instead of raw mm where one
  already exists; add a new unit in `units:` if a magic number appears more
  than once.
- For new footprints, prefer `ceoloide/*` upstream; only drop a custom one in
  `imochoa/` if upstream lacks it.
- Do not edit ZMK / Zephyr / firmware files (`zmk/`, `zephyr/`, `firmware/`,
  `modules/`, `config/`, `.west/`) unless explicitly requested.
- `pnpm` is the package manager here (not npm/yarn). `just` is the task runner.
  A Nix flake (`flake.nix`) provides `kicad-cli`, `freerouting`, etc.
